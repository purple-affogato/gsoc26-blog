Week 1: MPCP Implementation

This post marks the first week of my GSoC project with RTEMS! ˖₊‧⁺˖.𖥔 ࣭ ˖๋ ࣭ ⭑ My current goal is to finish integratingMPCP into RTEMS by the time by midterm evaluation rolls around.

My progress so far has been on applying the original patch from the research paper that inspired this project and beginning testing of the MPCP implementation. I used git apply --reject --include="path/to/file" to carefully read through the implementation so that I understand it, as well as separate the DPCP & MPCP implementations. Along the way I’ve also been taking notes on what each change in the patch does.

The files mpcp.h and mpcpimpl.h are the main code additions from the research group, while the rest adds usage of the functions/structures/macros/etc. of MPCP to the RTEMS Classic API.

Outside of just coding, I also reviewed RTEMS’ coding standards and the original paper on MPCP by R. Rajkumar. These helped me to:

  1. Understand what improvements I need to work on to the original code so that the MPCP implementation adheres to RTEMS’ standards.
  2. Understand what certain elements of the patch might’ve been meant for. For example, one part of the patch adds a new function called _Thread_queue_Enqueue_busy(), which I initially was confused on its purpose as there were no comments describing what it does. My mentor suspected it had to do with busy-waiting that is needed for MPCP and advised me to check what the actual definition of MPCP entails to be able to comprehend what different parts of the patch were for.

Some other facts about MPCP include that it specifically uses a priority queue, follows the idea that when a task’s critical has higher priority over other tasks in their non-critical sections, and takes advantage of static binding (a task can only run on its host processor) to improve the ability of tasks to complete by their deadline. These factors should also be considered in MPCP’s implementation in RTEMS.

At the time of writing this, the implementation itself does seem to work on a basic level! It builds succesfully and is capable of passing a rudimentary test I wrote that tests the creation, obtaining, release, and deletion of a single MPCP semaphore:

#include <stdlib.h>
#include <rtems.h>
#include <stdio.h>
#include <assert.h>

static void Init( rtems_task_argument ignored )
{
    (void) ignored;

	rtems_status_code sc;
	rtems_id sem_id;
	rtems_task_priority prio;
	
	// creating the MPCP sem
	sc = rtems_semaphore_create(
		rtems_build_name('M', 'P','C','P'),
		1,
		RTEMS_BINARY_SEMAPHORE | RTEMS_MULTIPROCESSOR_PRIORITY_CEILING,
		2,
		&sem_id
	);
	
	assert( sc == RTEMS_SUCCESSFUL );
	printf( "Created MPCP semaphore.\n" );
	
	// obtaining MPCP sem
	sc = rtems_semaphore_obtain( sem_id, RTEMS_WAIT, 4 );
	assert( sc == RTEMS_SUCCESSFUL );

	// check priority was raised
	sc = rtems_task_set_priority( RTEMS_SELF, RTEMS_CURRENT_PRIORITY, &prio );
	assert( sc == RTEMS_SUCCESSFUL );
	assert( prio == 2);

	printf( "Obtained MPCP semaphore.\n" );

	// pause for a bit
	rtems_task_wake_after( 10 );

	// releasing MPCP sem
	sc = rtems_semaphore_release( sem_id );
	assert( sc == RTEMS_SUCCESSFUL );

	// check priority was reset to old value
	sc = rtems_task_set_priority( RTEMS_SELF, RTEMS_CURRENT_PRIORITY, &prio );
	assert( sc == RTEMS_SUCCESSFUL );
	assert( prio == 4 );

	printf( "Released MPCP semaphore.\n" );

    // delete the semaphore
    sc = rtems_semaphore_delete( sem_id );
    assert( sc == RTEMS_SUCCESSFUL );
    
    printf( "Deleted MPCP semaphore.\n" );

	exit( 0 );
}
